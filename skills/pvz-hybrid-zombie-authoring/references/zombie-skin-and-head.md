# 僵尸外观：三件套 / 换头三节点 / 头对位

> 本文件是 `pvz-hybrid-zombie-authoring` 的 reference。
> 通用部分（经典 reanim 二进制、`.dat` 规格、抠像管线）与 `pvz-hybrid-mod-authoring` 同源，这里只讲**僵尸侧**。

## 1. 「三件套」不是一个 PNG

角色外观 = `<Skin>.dat` + `<Skin>.tres` + `<Skin>Atlas.png`，三个都要进包
`Resources/Animations/`，且 `Sprite` 场景里的 `flashAnimeData` 指向**包内** `.tres`
（`.pmod` 之间**不能互引** —— 想把植物包的外观搬进僵尸包，得把三件套**复制**进来）。

**clip 布局**（官方直转的通用约定，本仓实测）：

| clip | 帧范围 | 说明 |
|---|---|---|
| `BodyIdle` | `0..24` | 身体待机 |
| `HeadIdle` | `25..49` | 头部待机 |
| `HeadFire` | `50..86` | 头部开火 |
| `Walk` / `Eat` / `AngryWalk` / `AngryEat` / `Death` / `Gasp` | 见各角色 | 僵尸特有 |

`trueFrameRate = 180`；**发射帧 = `HeadFire.start + 12`**（本包 = 62）。
帧号是**全局单调**的（头段接在身体段后面，不是每段从 0 开始）。

## 2. 经典 reanim → 重置版直转（首选路线）

`Asset/Anime/Character/**/*.reanim.compiled` 是经典版的逐帧数据；重置版用 `.dat` + 图集。
转换要点（全部由「内置同角色双引擎对照」反推 + 数值验证）：

1. 解析 `.reanim.compiled`（二进制，含轨道/变换/帧序列）；
2. 生成 `.dat`（头部 18 字节 + 每元素 30 字节）与图集 PNG；
3. 生成 `.tres`（帧 → 图集区域的映射、`media_rects` 等）；
4. 生成 `skin_params.json`（本次转换的标定结果，便于复查）。

**`.dat` 二进制硬判据**（写完必须自证）：

| 项 | 判据 |
|---|---|
| 解析终点 | 必须**恰等于文件长度**（多一字节少一字节都是错） |
| 像素区 | 逐字节 == PNG 真解码结果 |
| 事件段 | `u16 条数`；`frameIndex` 是 **u16**；**Command 在前**（`("fire", "")` 而非 `("", "fire")`） |
| 开火事件 | 必须有 `{"Command":"fire"}`，否则「只有动画没子弹」 |

## 3. ★★ 换头必须走「三节点」（子精灵必被父代画）

**症状**：给子精灵换贴图后，画出来的是**别的角色的碎片拼贴**。

**根因**：`AdobeAnimateSprite.CollectOwnedChildBindings`（`:5385`）只看节点类型，
`_Draw`（`:9534`）首行就 `return` ⇒ **子精灵的切片一定被父批次代画、采样父那一张图集**。
⇒ 子精灵自己的 `forceLocalRender` **完全失效**。

**修法（唯一可行）**：`Sprite` 场景里身体下留三个节点：

```gdscript
[node name="HeadShadow" type="Node2D" parent="."]
visible = false                        # + 全部层 false ⇒ 零切片，不画任何东西
# 只为吃 UpdateChild() 的每帧定位

[node name="HeadHolder" type="Node2D" parent="."]     # 普通 identity 容器，打断「父代画」

[node name="Head" type="Node2D" parent="HeadHolder"]
z_index = 1                            # ★ 压住身体（见 §5）
```

两头（`HeadShadow` 与 `Head`）的 `scale` / `offset` / `offsetRotate` **逐字相同**，
位姿由插件每帧从影子抄给可见头（`Position` + `Rotation`）。
⚠️ 别写 `insertLayerId = -1`（默认值 ⇒ 回落**顶层** ⇒ 画在最前）；要让子精灵**压在父下面**
必须显式写 `insertLayerId = <父精灵 layerDictionary 的 id>` —— 详见 **§9**。

**原版头部的 7 个图层必须在身体上显式关掉**：

```gdscript
Animation/LayerVisible/<原头那 7 层> = false
```

（内置 `ZombiePaper.tscn` 把这 7 层写死成 `true`，不覆写就从头盔底下透出来。）

## 4. 头对位：反解 `offset`（别手抄数字）

引擎的真实变换（`AdobeAnimateSprite.UpdateChild()`，`AdobeAnimateSprite.cs:5259-5281`）：

```
子精灵每帧被覆盖：Position = <被跟随图层 L 的 pose>.Origin + <父精灵的 offset>
                 Rotation = <被跟随图层 L 的 pose>.Rotation + child.offsetRotate
绘制自己美术时：transform = transform.Translated(child.offset)     （:7044 / :7071 / :7362）
```

* **僵尸朝左** ⇒ `scale = (-1, 1)` 横向镜像；`offset` 活在横翻矩阵里。
* ⚠️ **`offsetRotate` / `rotation` 单位都是弧度**（官方样本写 `-0.25` = −14.324°，不是 −0.25°）。
* ⚠️ **改「屏幕位置」不能直接加到 `offset` 上**（横向会反向）。必须加在**锚点**上再反解：

```
目标中心的屏幕位移 = <你想要的 dx, dy>
⇒ 反解 offset = solve(follow_layer, body_frame=0, shift=(dx, dy))
```

**三条姿态开关**（`usePos` / `useRotate` / `rotation`）：

| 口径 | 场景里怎么写 | 效果 |
|---|---|---|
| 跟动画摆（默认） | **三行一个都不写** | 引擎每帧覆写 `Position`+`Rotation` ⇒ 头跟 `anim_head1` 逐帧摆 |
| 摆正不摆头 | `useRotate = false` + `rotation = <常量弧度>`（**必须成对**） | 引擎不再覆写 `Rotation`，但 `Position` 仍跟随 |

⚠️ 只写 `rotation` 不写 `useRotate = false` ⇒ 那是个**死值**（每帧被覆写），只会误导后人。
⚠️ 换头/换身体/改偏移之后，`offset` **必须重解**（它和被跟随层的旋转耦合）。

## 5. 层级：能独立渲染的写 `z_index`；**被父代画的无效**（见 §9）

全局绘制排序键的**第一位**是 `ZIndex`（`AdobeAnimateSortPath.cs:37-76`；统一排序
`AdobeAnimateRenderManager.cs:753`），而 `EffectiveZIndex` 是**沿父链累加** Godot 的 `z_index`
（`AdobeAnimateSprite.cs:6513-6531`）⇒ **给可见头写正数**（`z_index = 1`）就保证压在身体/护具之上，
**对树序不敏感**（`move_child` 那种「排到后面」不可靠）。

* 影子（`visible = false` + 全层 false，零切片）**不写** `z_index`（写了无意义还误导）。
* 「头部层级必须高于身体」是**无开关的不变量** ⇒ 断言写死「必须是正整数」，别写成可关的开关（防假绿）。
* ⚠️ ⚠️ **前提**：`z_index` 只对**独立渲染**的精灵有效。一旦该精灵被**父精灵代画**
  （§3 的递归收集规则），它的 `z_index` **根本不进排序键** ⇒ 想调层只能用 `insertLayerId`（§9）。

## 6. ⚠️ 自制 `.dat` 皮肤静止 ⇒ 运行期切本地 CPU 位姿渲染

自制 `.dat` 走了非官方路径时，动画会静止（ESC 一次跳一帧）。修法：**运行期**
给这些精灵设 `forceLocalRender` + `forceCpuPoseRender`，并每 N 帧全树扫描补齐
（插件里做成一个可复用的静态 `Patch(...)`）。官方直转的素材一般不需要。

## 7. 换头后的验收（离线能验一半）

| 项 | 怎么看 |
|---|---|
| 两头三件套逐字相同 | 场景文本比对（`scale` / `offset` / `offsetRotate`） |
| 头没悬空 | 几何门算「新头包围盒覆盖原头包围盒的面积比例」（本仓 ≥ 0.60 为过） |
| 屏幕位移符合预期 | 几何门算 `screen_delta(offset)`，与目标 `(dx, dy)` 比（容差 1e-3） |
| 原头 7 层已关 | 场景文本断言 |
| 层级 | `z_index` 是正整数 |
| 剩下的 | **进游戏看**（离线验不了「好不好看」） |

## 8. ⚠️⚠️ 层可见性会「静默失效」——引号必须包住**整条**属性名

**症状**：多出一个头 / 该关的层（皇冠、光环、披风、另一张脸）怎么都关不掉，且**零日志**。

**根因**：层名含**空格或非 ASCII** 时，引号只包末段 ⇒ 整行**完全无效**：

```
正确： "Animation/LayerVisible/图层_1" = false      ← 官方 6941 个 .tscn/.tres 零例外
正确： Animation/LayerVisible/anim_idle = false     ← 纯 ASCII/数字 ⇒ 裸写
错误： Animation/LayerVisible/"图层_1" = false      ← 只包末段 ⇒ 这一行不生效
```

`AdobeAnimateSprite._Set()`（`:3001-3017`）收到的属性名**带引号** ⇒
`layerDictionary.ContainsKey(name)` 为假 ⇒ 直接 `return true`（不报错、不生效）
⇒ 该层保持 `_layerVisible` **初值 `true`**（`:9049-9069`：没写进数组的下标一律按可见算）
⇒ **永远可见**。

**实测后果**：`HeadShadow` 的「全层 false ⇒ 零切片」白写 6 层
（`图层_1` 皇冠 / `图层_3` 光环 / `图层_67 复制` 火圈 / `图层_69` 花瓣 /
`cloak1 复制` 披风 / **`skin2_2 ` 另一张脸** —— 全是「含空格或非 ASCII」的名字）
⇒ 身体上**多长出一个完整的头**。

**规程**：
1. 生成器统一 `_prop(key)`：判据作用在**整条 key** 上
   （`f'"{key}"' if (" " in key or not key.isascii()) else key`）。
2. 常驻自检 `_bad_prop_keys(text)`：扫 A 型（只包末段）/ B 型（该包却裸写），命中即 FAIL；
   另加金标断言「含空格/非 ASCII 的层名必须以整条加引号形式出现」。
   ⚠️ 扫描只看「名字含 `/` 的属性路径」，跳过 `.tres` 多行字符串续行
   （那些行也含 `=`，例 `速度：[color=cc241d]慢[/color]`）。
3. 全库对照扫描：`.cache/_sq_quotefix_scan.py`（自己的产物 vs 官方 `Asset`）。**新建包必跑**。
4. 负向复刻：把 `_prop` 改回「只包末段」/「完全不包」，断言必须打红。
5. 定位「哪层是哪张图」用**逐层反查**：`layerDictionary`(名→id) + `mediaDictionary`(名→id)
   对齐 `sliceLayerIds`/`sliceMediaIds`。

## 9. ★★★ 被父精灵代画的子精灵，自己的 `z_index` 完全无效 ⇒ 只能用 `insertLayerId`

**症状**：给子精灵写了 `z_index = -1`（想压在父/身体下面），**一点用都没有**，它照旧画在最前面。

**根因链**（读唯一带 `.cs` 的那棵解包树）：

| # | 环节 | 源码 |
|---|---|---|
| 1 | 排序键顺序 `ZIndex → TreeOrderPath → LayerOrder → DrawOrder → NestedPath → StableOrder` | `AdobeAnimateSortPath.cs:37-76` |
| 2 | 「被父代画」判定 | `AdobeAnimateSprite.cs:9559-9567` `IsRenderedByParentSpriteForRender()` |
| 3 | 谁算子精灵：**递归**收集任意深度的 `AdobeAnimateSprite`，并**钻过非精灵中间节点** | `AdobeAnimateSprite.cs:5365-5402`（`CollectOwnedChildBindings`） |
| 4 | 子树 `ZIndex` 取的是**父精灵**的 `snapshot.EffectiveZIndex`（一路原样下传） | `AdobeAnimateDrawItemBuilder.cs:68 / 232-234`、`:833-856` `AppendChildSprites` |
| 5 | 真正生效的键：`TryGetChildRenderLayerForRender` → `ResolveSpriteChildInsertLayer` = `child.insertLayerId >= 0 ? insertLayerId : ResolveTopInsertLayerId()` | `:7986-8003` / `:8039-8050` |
| 6 | 默认 `insertLayerId = -1` ⇒ 回落**顶层** ⇒ 画在最前；`AutoInsertChildSprites` 只对 **直接子节点** 自动插入（要求 `child.GetParent() == this`） | `:389` / `:5547-5577` |

**结论**：挂在普通 `Node2D` 容器下的子精灵（换头三节点、贴图光环…）**逃不掉**第 3 条，
⇒ 想调层**只能**显式写 `insertLayerId = <id>`，id 按**父精灵**的 `layerDictionary` 解释。
`z_index` 只留作**非托管渲染路径**（编辑器 / 管理器未就绪）的兜底。

**取值**：看父精灵 `.tres` 的 `layerDictionary` —— 一般 `id = 0` 是内建隐藏背景板
（如 `_ground`，场景里 `= false`），可见层从 `1` 起。取 `0` ⇒ `LayerOrder 0 < 1`
⇒ **严格画在每一片父美术之前** = 完全在父**后面**。

官方同款：`ZombieDiscoFire.tscn` 的子精灵 `ZombieDuckytube` 写
`Layer = 15` + `insertLayerId = 15` + `followParentSpriteLayerId = 15`（「插到父傀儡第 15 层」）。

⚠️ 反面（**仅限「静态定位」的子精灵**）：别写 `Layer` / `followParentSpriteLayerId` ——
那两个是「跟随某层的 pose 定位」，不是排序；静态定位的子精灵写了只会去跟一个隐藏层，纯噪声。

★★ 但换头三节点的 **`HeadShadow` 恰恰就是要用它们**（`Layer = insertLayerId =
followParentSpriteLayerId = <跟随层>`，**三行同值**）—— 那是它**唯一**的定位来源
（`visible = false` + 全层 false ⇒ 零切片，只为吃 `UpdateChild()` 的每帧定位）。
* `followParentSpriteLayerId` 是 **1-based、引擎不减一** ⇒ 写 19 就跟随 `Layer == 19`
  （经官方用例交叉印证：`ZombieDiscoFire.tscn` 的 `ZombieDuckytube` 写 15、
  `ThreePeater.tscn:29/45/61` 三个头分别写 14/21/9）。
* ⚠️ **换这个值必须重解 `offset`**（同「改 `head_scale` 必须重解」）。
* 选哪个层、怎么判定好坏 ⇒ 见 **§11**。

## 10. 尺寸 / 位置类需求（「调大/调小一点」「往上挪一点」）—— 别目测猜，要「量出来」

目测猜倍数必然被下一张图推翻（本仓实测连续四轮 3.5 → 3.0 → 2.5 → 2.0 倍）。
用户给出**目标截图**时走三步闭环：

| 步 | 做什么 | 关键坑 |
|---|---|---|
| ① 量参考图轮廓 | 从**四边泛洪**取「最大非背景连通块」：背景判据 `g − max(r,b) > 8`（草坪）或 `max(r,g,b) < 45`（黑框） | 用「四边众数色」当背景会被黑框骗 ⇒ 全图都算角色 |
| ② 扫候选倍率 | **离线合成渲染**：读共享图集 + `Manifest`（每 media 的页号 / 页内 rect），按 `身体 / 头 / 子精灵` 三条变换链喂 `PIL` 的 `AFFINE`（逆矩阵）；量**真实渲染像素**的 bbox | 变换链里**别乱塞根节点 `offset`**（它只在锚点用一次）；子精灵的显示空间 = 美术空间（见 `offset` 那条铁律） |
| ③ 目视复核 | 参考图 + 候选图**按同一高度归一**并排拼一张 | 归一化要**剔掉尺寸恒定的装饰**（如固定 200px 的光环），否则会把倍率差异稀释掉 |

**判据**：至少取两个独立量（例「头高 / 全身高」与「头高 / 可见身体高」），
挑**落在参考图两侧最近**的一档；取整档便于复现。
⚠️ **全渲染比 ≠ 分割掩码比**（掩码会被背景混色吃掉边缘）⇒ 以全渲染比为准，掩码只作交叉印证。

🔁 **改完固定动作**：`A = rot_scale(θ, −s, +s)` 含节点 scale ⇒ **改了 `head_scale` 必须重解 `head_offset`**，
再同步「金标常量 + 文档口径串」，最后重生成 + 重跑全套闸门（否则文档 vs 产物对账必红）。

### 10c. **相对放大**（「改为**现在的** 1.2 倍」）—— 三条口径

用户说「改为**现在的** N 倍」= **在上一次定标结果上再乘 N**，不是重新标定绝对值，也**不是**「N 倍于原素材」。
（实例：`2.0 倍 → 「改为现在的 1.2 倍」→ 2.4 倍`，`head_scale 0.9 → 1.08`。）

1. `head_scale = 旧值 × N`。
2. 解 `offset` 时**沿用当前 `shift`** —— 否则位移会被一起「解掉」，头会掉回原位
   （第一轮的「上移 20.16px」就是这么丢的）。`solve(shift=…)` 语义 = 把位移加在**锚点**上。
3. **旧 `offset` 不许复用**，必须重解（实测残差 `5.2px` 量级）。

⚠️⚠️ **但「沿用 `shift`」只在「没换过跟随层」时成立**：`shift` 是相对 `Placement.target`
（= **跟随层**全帧并集中心）的位移 ⇒ **一换 `head_follow_layer`，`target` 就变**，
历史 `shift` **不再等价**（第十五轮实测：拿 `shift=(0,-20.1565)` 去解，`screen_delta` 给的是
`(-3.7002, 30.2434)`）。⇒ 换过层之后，**位置一律用「头块中心的绝对坐标」表述**，
用 `solve_for(PL, target)` 反解（见 §10c-2）。

### 10c-2. **同时改「缩放」+「位置回调」**（第十六轮）—— 必须**一次解**，别分两步

用户「位置**回调至之前的状态** + 缩放改为**原有的 2.0 倍**，**两项同时生效且相互不冲突**」：

* 为什么「会冲突」：`A` 含节点 scale ⇒ 光改 scale 头就横竖跑偏
  （实测「旧 `offset` 配新 `scale 0.9`」偏差 **16.63px**）。
* ✅ 正解 = **固定目标、换 scale 重解**：把目标设成**上一版头块中心的绝对坐标**，
  在**新 scale** 的 `Placement` 上 `solve_for(PL_new, target)` ⇒ **位置不动、尺寸变**。
  两项天然同时成立（这就是「不冲突」的证书）。
* 校验（都能量出来）：头块中心与上一版 **偏差 `0.00000000`**；整头宽高比 = `新S / 旧S`
  （实测 `0.8333` = 2.0/2.4）；旧 `offset` 配新 scale 的偏差 **非零**（反向印证必须重解）。
* ⚠️ **别用 `_sq_head_place.py` 解** —— 它写死 `follow=19`（第十四轮前口径），**已过期**。
  用 `.cache/_j16_resize.py`（或自己 `solve_for`）。
* ⚠️ **「之前的状态」常常有二义**（上一版↔更早某一版）⇒ 先问；用户若回「继续任务」，
  取**保守**（= 撤销**最少**、最接近用户显式要求过的那个状态），并把另一档的数值一并给出。
* ⚠️ **字面量精度**：offset 要写成 **`repr` 形式**（`27.4960` 的 repr 是 `27.496`）；
  生成器的文档断言带右边界 `(?![\d.])`，docstring 写成 `27.4960` 会**判红**。

✅ **「原地放大」怎么证**：不靠目视，靠**落点中心逐字不变** ——
解出的头块落点中心应与上一倍率**完全相同**（例 `(-10.20, -55.26)`），`screen_delta` 也逐字不变。

⚠️ **别用启发式取块量「放大前后」的尺寸**：「画面里最靠上的橙色大块」在 2.0 / 2.4 两倍率下取到的
**不是同一块**（火焰花瓣逐帧变）⇒ 实测给出 `1.19` 这种**假比值**。尺寸比一律报**解析值**
（`1.08 / 0.90 = 1.2`）。

🔎 **对照图最干净的画法**：同 `box` / 同 `k` / 同 `shift` 渲染两张（只有倍率不同）⇒ **像素坐标系一致**，
可以直接画**解析解出的锚点十字**；⭐⭐ 且离线渲染器落盘的是 **RGBA（透明底）** ⇒ 想要「旧轮廓叠在新图上」，
**直接取 alpha 通道**（`ImageFilter.MinFilter(3)` 腐蚀后相减 = 边界），**完全不需要启发式取块**。
（实例脚本 `.cache/_sq_scale12.py`：BEFORE / AFTER / OVERLAY 三格。）

### 10b. 位置类需求（「头往上一点，跟那张图一样」）—— 一样别目测，且**锚点必须「刚性」**

拿「目标截图」与「现状截图」**两张真实图**比，**不经过离线渲染**（离线渲染的帧 / 姿势未必与实机一致）。
工具形态：`.cache/_sq_overlay2.py <out.png>`（输出红/青叠加图 + 打印位移）。

**四个坑**：

1. 两图**画幅 / 角色占比**通常不同 ⇒ 绝对 y 不可比，必须先找「两图都有、且与**头无关**」的身体标尺。
2. **标尺不能选会被遮挡的量**：实机截图的裤子常被**脚底光环 / 特效**截断 ⇒ 裤高跨图不可比。
   正解 = **头宽**（若头尺寸已定标过 ⇒ 两图头宽就是共同比例尺）。
   ⚠️ 只能比**宽** —— 头的**高**受火焰帧影响。
3. **头块本身要取「画面里最靠上的橙色大块」**，不能用「最大橙块」——脚底光环常比头大好几倍
   （实测脚底光环 `n=6701` > 花瓣 `n=1575`）。
4. **头的锚点必须「刚性」**：头 bbox 含**火焰花瓣**，而火焰是**逐帧动画** ⇒ 顶 / 底 / 中心都会被帧差污染。
   正解 = 头块 bbox **内的黄色块**按面积降序取前两块：**第 1 大 = 脸**、**第 2 大 = 王冠**（≈13×15）。
   两者随整个头平移、**不随火焰变形**。实测：刚性判据给 `+20.2`，而「头块中心」只给 `+15.9`
   ⇒ **差 20%**（这就是第一版差点交付错值的原因）。
   （黄上衣同色，靠「**限定在头块 bbox 内**」排除。）

**落地**：位移**加在锚点**上（`Placement.solve(shift=…)`）⇒ 反解出新的 `head_offset`。
⚠️ **别把位移直接加到 `offset` 上**：`A` 含 `sx=−1` 横翻 + 交叉项 ⇒ 横竖都会变。
离线渲染核对时用 `_sq_preview.py --shift=dx,dy`（同样是加在锚点上，语义与 `solve(shift=…)` 一致）。


### 10d. **没有参考图**的尺寸 / 位置需求（「再大一点」「往右上方移一点」）—— 量级只能由「口径」定

用户**没给目标截图**时，§10 / §10b 那套「量出来」的前提（有图可比）不成立，
但**铁律 30 仍然禁止目测猜**。正解 = **先问、问不到就按口径定，并把「这个量是默认值、一句话可改」写清**：

1. **先问量级**：给几个候选（如 8 / 12 / 18px）让用户挑。用户若直接回「继续任务」不选 ⇒ 走第 2 步。
2. **口径法**：从**本项目历史**里找同义先例，取**保守**值。实测先例：
   * 舞者头「右上偏移」第七轮 = **18px**；
   * 女王头「往上一点」第十一轮 = **20.16 显示px**（这是**量出来**的，不是猜的）。
   * ⇒ 第十三轮「两个头一起往右上方移一点」取 **右上各 12px**（比两个先例都小 ⇒ 保守）。
   * 女王头「**整体向上移动一点**」第十五轮 = **8px**（先例 20.16 / 18 之上再取更小 ⇒ 纯上移、
     x 不动；工具 `.cache/_j15_shift.py --char queen --dy 8` ≈ 复用 `solve_for`）。
3. **一句话可改**：文本里明确「12px 是没参考图时的口径默认值，要改只换**累计 `shift`** 重解」。
4. **多角色同一句话** ⇒ 用**同一增量**（同一量级），别一个 12 一个 18。
5. 位移**加在锚点**上、`offset` 用**累计 `shift`** 重解（不是增量），残差 0 + `screen_delta` 逐字 = `shift`。

⚠️ 对照图最干净的画法：**同一个 `box` / `k`** 渲「移前 / 移后」两格，**灰虚线十字**画对面那格位置、
**亮色十字**画本格解析锚点（锚点现算 `Placement(...).target + shift`，不手抄）。（实例 `.cache/_sq_shift13.py`。）

★★ **隐藏坑：离线渲染器 `_sq_preview.py` 的 `--mult` 带一个 0.45 的隐藏基准**（`S = 0.45 × mult`），
而 `0.45` 是**女王包的历史口径** ⇒ 给**别的角色**渲图时极易搞错：
实测把舞者的 `head_scale 1.0` 写成 `--mult 1.0` ⇒ `S = 0.45` ⇒ **头被渲小 2.2 倍**。
⇒ 该脚本已新增 **`--head-scale`**（直接给**绝对** `S` = 生成器里的 `head_scale`）；
**给任何角色渲图一律优先用 `--head-scale`，别用 `--mult`**。

⛔ **实测续**：上面那轮「口径法」取的 12px，**当天就被用户「回调到上一版」推翻了** ——
回滚 = **只改生成器参数（`head_offset` + `GOLD_*_HEAD_OFFSET`）后重生成**，因参数驱动 + 幂等，
pmod **逐字节**回到上一版（`26 206/aaa35fc2484658d2` → `26 203/6178768a38cd46e8`，`TARGET MATCH: True`）。
⇒ 两条经验：⑴ 「无参考图 ⇒ 量级由口径定」**只是方法**，取值随时会被推翻 ⇒ **动手前先快照当前版**
（`.cache/_sq_r13_snapshot/` 式），保证回滚本身也可逆；⑵ 回退历史时**别删旧叙述**，改成标 **【已回滚】** ——
删掉的话，对账脚本里「历史值在位」那类断言会集体变红。
⑶ 回滚必须**同步 4 处**：生成器参数/金标、负向脚本锚点、对账脚本（含**过期值清单要「换向」**：
把已回滚的指纹加进去、把当前值拿出来）、文档/记忆。

## 11. ★★★ 选择 / 更换「被跟随层」—— 抬/低头交接处「头身衔接不自然」的正解

**症状**：跳舞 / 摆头动画里，**抬头动作那一帧**头与身体（脖子）出现明显**断层** ——
头猛地往上跳一下，或飞离脖子留出空隙。**逐帧静态看不出来**，只在**两个 clip 的交界帧**
（θ 突变处）最凶。

**根因**：头是**刚体**（离线合成渲染），而它的枢轴 = **被跟随层的 pose 原点**：

```
child.Position  = <层 L 的 pose>.Origin   + <父精灵的 offset>
child.Rotation  = <层 L 的 pose>.Rotation + child.offsetRotate
```

头底缘离枢轴越远（第十四轮当时口径 = 放大 **2.4 倍**；★ 第十六轮已回 **2.0 倍**），
该层一帧内旋转 `Δθ` 就把头甩出去（`∝ R·sinΔθ`）。
而**原版原头组不是刚体**（逐帧换形）⇒ 刚体头**无法**逐像素复刻，只能最小化「相对脖子的漂移」。

**两条判据（缺一不可）**：

| 判据 | 定义 | 特性 |
|---|---|---|
| ① 1D 接缝 | `gap(f) = 头并集 bbox 底边 − 脖子层 bbox 顶边`；指标 `max_f \|Δgap\|` | 对**显示空间刚性平移完全不敏感** ⇒ 可自由挪枢轴 |
| ② 2D 偏差 | `dev(f) = 头并集 bbox 中心 − 原版原头并集 bbox 中心`；指标 `max\|dev − dev(ref)\|` | 防止 ① 被「底边」掩盖横向摆动 |

* ⚠️ **只信 1D 会翻车**：把枢轴挪到「1D 最优」能把 1D 降到 `2.67px`，但 **2D 劣化到 `16.0px`**（实测）。
* ⚠️ 脖子参考层选 **`Zombie_disco_upperbody`**（女王 L15 / 舞者 L12），
  **别**用 `Zombie_disco_medalion`（那是胸章，位置偏低）。

**修法 = 换跟随层**（不是挪枢轴、不是 `useRotate = false`、更不是 `pause`）：

1. 在身体片里挑一个「抬头交界处**不转**（或与身体**同步**转）」的层。
   本仓胜出层 = **`anim_hair1`**（女王 L28 / 舞者 L22）：女王该层 **θ 全 clip ≡ 0.000°**、
   node 是**纯离散平移** ⇒ 头不再跟着下颌转。
2. **★★ 必须重解 `offset`**（同「改 `head_scale` 必须重解」—— `A` 含节点 scale 与 θ）。
   重解口径 = 让**参考帧**（θ 确定的那一帧）的头块落点**逐字不变**
   ⇒ 参考帧外观**逐像素不变**（实测差异 `0.00000000px`）⇒ **换层是零观感成本的纯「转轴替换」**。
3. ⚠️ **「每层旋转都同步」的角色（如舞者），1D 数字看不出收益**（甚至略差）
   ⇒ **必须**靠 ② + 视觉对照图定夺。

**视觉定夺工具**：`.cache/_j14_neck.py` —— 同一帧横排 `orig / 旧层 / 候选层`，紧裁到颈肩，
候选层 **offset 按「保落点」重解**再渲。一跳 / 一飞离，一目了然。

**副作用（要主动交代）**：
* 跟随层若在某 clip **缺切片**（如 `Death`）⇒ 按 `useFollowVisible` 规则**该段头隐藏**。
  多数情况原版那段本来也没有可见头 ⇒ 是**正确**行为，但仍应实机确认。
* 「头不再随身体抬起」的地方（如 `ArmRise`）要看该层 node 平移是否仍与 θ 上仰的竖直效应一致。

**顺带（同一症状的次要项，★ 可选手段）**：头自身播的 `Idle` 会在原地**横滑**（本仓整颗头
≈ 13.2 局部单位 = 显示 14.3px）⇒ 可给它写 **`timeScale = 0.0`** **冻结**（`[Export]`，
运行期可写、**不回存场景**）。⚠️ **别用 `pause`** —— `ApplyRuntimeParentState`（`:5475-5478`）
会 `pause = parent._pause` 覆写掉。

⚠️⚠️ **这是「可选」，不是默认口径**。向日葵女王包在**第十五轮已按用户要求【取消】**该冻结
（`HEAD_TIME_SCALE = None` ⇒ 两个头节点**都不写** `timeScale`，引擎用默认 `1.0`，头恢复自播 Idle），
并把自检断言**翻转**为「不得出现 `timeScale`」、负向用例改成「注入即打红」。
理由：当初冻结的收益仅 **2.2~4.5px**（女王 12.176→7.637、舞者 8.177→4.897），
而**取消代价很小**、且用户更想要头自播的生动感。
⇒ **要重新冻结**：把常量改回 `0.0`，**必须同步**① 翻转 `self_check` 断言（`is not None` → `is None`）、
② 改写负向用例（「必须出现」而非「注入即红」）。
`⚠️` 影子与可见头**若写就要都写** `timeScale`（逐字一致）；`Aura` 之类**该转**的精灵**不写**。

### 11b. ★★★ 头的位姿必须**同帧** —— `process_frame` 早于 `_process` ⇒ 插件落后 1 帧

**症状**：**快速动作**（抬头 / 收头 / 转身）时头与身体**错位**，看起来像「分离 / 脱离」；
慢动作**完全正常**。⚠️ **离线合成渲染永远复现不出来**（它没有时序）。

**根因**：可见头**自己不跟层**（它的 `parentSprite` 不指向身体 ⇒ `UpdateChild()` 无从取位姿），
靠插件每帧从**影子**抄 `Position`/`Rotation`。若插件挂在 **`SceneTree.process_frame`**
（它**早于所有节点的 `_process`**），而影子的位姿恰是身体精灵**在 `_process 里**被
`UpdateChild()` 改写的 ⇒ **读到的永远是上一帧的值** ⇒ 头永远落后身体 1 帧。

* 正常帧位移 < 1px ⇒ 看不出来；**跨 clip 交界帧**（node 一帧可跳 **20~33px**）
  ⇒ 头/身错位 20~33px ⇒ 用户报「分离」。

**修法（推荐 ①，改动最小、失败不更差）**：

1. ★ **`CallDeferred` 覆盖**：**保留**原有 `process_frame` 里的同步（兜底），紧接着再排一个
   `Callable.From(new Action(SyncHeadPairs)).CallDeferred()` ⇒ 帧末（所有 `_process` 之后、
   绘制之前）用**当帧**位姿**覆盖**旧值；即便它落到下一帧初，此刻影子仍是当帧值 ⇒ 同样正确。
   ⚠️ **别只删** `process_frame` 那次 —— 若 `CallDeferred` 因故不执行，头会**静止**（比现在更糟）。
2. **让可见头自己跟层**：给可见头也写 `followParentSpriteLayerId`（`parentSprite` 会自动
   `FindParentSpriteAncestor()` 解析到身体精灵），引擎**同帧**更新它。官方同款：
   `ThreePeater.tscn` 三个头各自跟层。⚠️ 但 `_parentSprite != null` 会改变
   `GetRenderSortRootForRender()`（`:4987`）的取值 ⇒ **有排序/层级副作用**，须实机确认头没被身体盖住。
3. 走方案 2 就**必须删掉**插件里的 `Position`/`Rotation` 抄写 —— 否则插件会用**旧值**覆盖引擎的新值。

**判定规程**：任何「头跟不上身体」的报障，先问三件事 ——
① 插件在**什么信号 / 时机**里同步？（`process_frame` / `_process` priority / `frame_pre_draw`）
② 影子位姿是谁在**什么时候**写的？（身体精灵的 `_process`）
③ 两者的**先后**是否保证「读当帧」？
⇒ 只查离线几何（接缝 / 偏差 / 缺帧）**永远查不出**时序类 bug。
