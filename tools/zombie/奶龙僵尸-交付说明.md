# 奶龙僵尸 · 交付说明

> 一个《植物大战僵尸杂交版》(Godot 4 + C#) 的僵尸 Mod：**普通僵尸的全部基础行为** + **每 10 秒一次的大笑控场**。
> 全部形象由你给的三份素材（奶龙站立图、奶龙大笑图、奶龙笑声音频）离线程序化扩帧而成，无第三方美术依赖。

- **Mod ID**：`nailongzombie`　**角色 Key**：`ZombieNaiLong`　**显示名**：奶龙僵尸
- **版本**：1.0.0　**作者**：云漫行
- **装机位置**：`%APPDATA%\Godot\app_userdata\植物大战僵尸杂交版\Mods\奶龙僵尸\`（已安装 + 已在 `enabled_mods.json` 登记）
- **可分发包**：`tools/zombie/奶龙僵尸.pmod`（828,651 字节，14 个文件）

## 一、★★ 「僵尸不会往前走」的真正原因（第 3 轮修复）

这一轮最重要的发现：**初版奶龙僵尸一步都走不了，而且原因不在插件里，在皮肤里。**

### 引擎的唯一前进机制

全仓只有 `GroundMoveComponent` 会平移角色 —— `grep TranslateForPhysicsFrame` 只命中它一个：

```csharp
// GroundMoveComponent.BatchUpdateValidated
Vector2 vector = TryGetGroundPosition(sprite, out groundChanged);   // 取 _ground 层的位姿
if (!groundChanged) { return; }                                    // 没变就不动
Vector2 vector2 = groundPosSave - vector;                          // 本帧位移 = 上帧 - 本帧
groundPosSave = vector;
_moveDelta = new Vector2(vector2.X * _moveScale.X, vector2.Y * _moveScale.Y);
TranslateParent(_moveDelta);                                       // 僵尸跟着平移
```

而它按**名字**去动画里找那一层（`groundLayerName = &"_ground"`，来自内置 `GroundMoveComponentDefinition`）：

```csharp
// GroundMoveComponent.cs:222
if (groundLayerName == null || groundLayerName.IsEmpty || ...
    || !parent.sprite.TryResolveLayerIdForRender(groundLayerName, out var layerId))
{
    _usingGroundLayerSource = false;        // ← 退化成「没有移动源」
}
```

**⇒ 皮肤里没有 `_ground` 层 ⇒ `_usingGroundLayerSource = false` ⇒ 位置恒定 ⇒ `_moveDelta == 0` ⇒ 一步都不动。**

初版的皮肤只有 `body` / `laugh` 两层，正好踩中。这不是插件能修的，因为位移的**唯一来源**就是这一层。

### 内置僵尸怎么做的（实测标定）

解析 `ZombieNormal.tres` 的逐帧切片数据（`probe_ground_motion.py`）：

| 项 | 值 |
|---|---|
| `_ground` 所在层 id | **0**（`layerDictionary` 里 `"_ground": 0`），`layerVisible[0] = false` ⇒ 不可见 |
| Walk1 (帧 44..90) | `originX` 从 **-10 线性走到 +40** ⇒ **+50 px / 47 帧** |
| 换算 | 12 fps ⇒ **12.77 px/s**（一格草坪 ≈ 6.3 s，合理） |
| 回跳 | 帧 90→91 从 +40 掉回 -10（Δ = -50），而 90→91 **正好是 Walk1→Walk2 的剪辑边界** |

**回跳为什么看不见**：`BatchUpdateValidated` 开头有

```csharp
if (sprite.pause || sprite.blend) { ResetGroundTracking(); return; }
```

剪辑切换会置 `sprite.blend` ⇒ 这一帧直接 `ResetGroundTracking()`（把基线清掉）⇒ 回跳被吃掉，不产生任何位移。

**⇒ 铁律：一个剪辑 = 一条完整锯齿，回跳必须落在剪辑边界上。** 放在剪辑中间会看到明显的倒跳。

### 本包的做法

- `nailong_skin.py` 新增 `_ground` 层（id 2），逐帧给一条锯齿；
- 元素 **`alpha = 0`**（只做根运动，不能画出来）、变换为单位矩阵 + 位移
  （必须非 Identity，否则 `TryGetManagedLayerPositionForRender` 会判无效）；
- 每个带根运动的剪辑（`Walk1` / `Walk2` / `Swim` / `LaughWalk`）**只放一条完整锯齿**；
- 不带根运动的剪辑（`Idle1/2`、`Eat`、`Death1/2`、`Waterdeath`）**完全不放** ——
  否则站着不动、啃植物、倒下时都会自己往前滑。

### ⚠️ 顺带纠正上一轮的一个错误结论

**`walkSpeedScale` 不影响移速。** 基类 `TowerDefenseZombie` 从不读它（只有 SwanRider / Bed 等派生类
把它乘到 `sprite.timeScale`），`_moveScale` 里也没有它。所以上一轮写的 `walkSpeedScale = 2.0`
**对速度毫无作用**（字段留着无害，但别再指望它）。

**真实的移速 = `GROUND_PX_PER_FRAME` 一个常量**（`nailong_skin.py`）：

```python
NORMAL_GROUND_PX_PER_FRAME = 50.0 / 47.0   # 内置普通僵尸实测速率
SPEED_TIER = 2.0                           # 「快」= 普通僵尸的 2 倍
GROUND_PX_PER_FRAME = NORMAL_GROUND_PX_PER_FRAME * SPEED_TIER   # ≈ 2.128 px/帧
```

⇒ 全部带根运动的剪辑统一 **25.53 px/s**（普通僵尸是 12.77 px/s，即 2 倍速）。改这一个数即可调全局移速。

## 二、时长与「边笑边走」（第 3 轮）

| 项 | 旧 | 新 |
|---|---|---|
| 控场 buff 时长 `PlantFreezeSec` | 1.0 s | **3.0 s** |
| 大笑姿态时长 `LaughHoldSec` | 1.4 s | **3.0 s** |
| 大笑用的剪辑 | `Laugh`（16 帧，只笑不走） | **`LaughWalk`（36 帧，边笑边走）** |

### 新增 `LaughWalk` 剪辑

**3 秒 = 36 帧 @12fps = 正好 3 个完整步态周期（12 帧/周期）。** 三条设计约束都有闸门强制：

1. **步态分量与 `_walk1(n=12)` 逐帧同值** —— 因为 `cycles/n = 3/36 = 1/12`，
   相位 `p = 2π·3·f/36 ≡ 2π·f/12`，与 Walk1 完全同相
   ⇒ **就是「正常走路」，不是另画一套脚步**（对应你说的「奶龙僵尸正常走路」）。
2. **36 = 3 × 12** ⇒ 播到任何一帧停下都落在完整周期上，3 秒窗口内必然整周期播完。
3. 笑意叠加用 **5 拍 / 剪辑**，刻意与步态（3 周期）不同频，避免同频叠出机械感。

根运动方面：`LaughWalk` 是**一条**锯齿（76.6 px / 36 帧），比 Walk1 的单周期更长，
但**每帧速率相同** ⇒ 大笑期间的前进速度和平时走路一致，不会忽快忽慢。

### 为什么必须用 `LaughWalk` 而不是原来的 `Laugh`

原 `Laugh` 剪辑**没有 `_ground` 层** ⇒ 那 1.4 秒里 `groundChanged = false`
⇒ **僵尸在大笑期间是停住的**（旧版即使修好了走路，一笑也会原地立定）。
`LaughWalk` 带上根运动，才做到「边笑边照常前进」。

另外插件的 `EnsureLaughClip` 用 **`SetClip`（直接赋值）** 而不是 `SetAnimation`：
后者会置 `sprite.blend`，而 blend 期间 `GroundMoveComponent` 会把位移整段丢掉
⇒ 每帧都 `SetAnimation` 会导致**完全走不动**。这是很容易踩的坑。

### 伤害类型怎么改的

`attackType` 只存在于 `AttackComponentDefinition` 上。做法：新建
`Scene/ZombieNaiLongAttackComponentDefinition.tres`（字段照抄内置 `AttackComponentZombieDefinition.tres`，
只多一行 `attackType = "Eat"`），再挂进本地 `ComponentSet` 的 `Components`。

覆盖能成立是因为组件集**按 `InstanceId` 合并**，且 `CanReplaceInheritedDefinition`
**强制要求 `ComponentTypeId` 与 `WireIndex` 与内置完全一致**，所以这三个值逐字对齐：
`InstanceId = "character.attack.0"` / `ComponentTypeId = "AttackComponent"` / `WireIndex = 0`。

> 内置类默认值本来就是 `"Eat"`，所以这是**等值覆盖**：行为零变化，作用是把规格显式固化进包。

## 四、大笑控场：攻速归零的 buff（第 2 轮修复）

`timeScaleInit = 0` **挡不住发射** —— 至少两条路径绕开了它：

- `FireComponent.cs:1687`（IZM 模式）只取 `buff.GetAttackSpeedMultiplier()`；
- `CannonComponent.cs:1344` 写的是 `flag ? 1.0 : parent.timeScale`。

被**所有**发射路径共同乘进去的只有 `buff.GetAttackSpeedMultiplier()`：

| 位置 | 表达式 |
|---|---|
| `FireComponent:1687` | 仅 `GetAttackSpeedMultiplier()` |
| `FireComponent:1693` | `timeScale × timeScale × GetAttackSpeedMultiplier()` |
| `FireComponent:3298` | `timeScale × GetAttackSpeedMultiplier() × …` |
| `CannonComponent:943` | 仅 `GetAttackSpeedMultiplier()` |
| `CannonComponent:1344` | `(flag ? 1.0 : timeScale) × GetAttackSpeedMultiplier()` |
| `CatapultComponent:538` | `… × GetAttackSpeedMultiplier() × …` |

它只认一个 key：

```
BuffComponent.GetAttackSpeedMultiplier() → BuffGet("AttackSpeedDown") → Math.Max(0.0, timeScaleValue)
```

**⇒ 控场期间给每株植物挂 `TowerDefenseCharacterBuffAttackSpeedDown { timeScaleValue = 0, time = 3 }`，
倍率 = 0 ⇒ 发射计时器永不推进 ⇒ 不挑组件、不挑模式，一颗都打不出来。**

用法与引擎自带先例一致（`TowerDefenseZombieBossEdgarII.ResolvePulse` 就是这么给全场植物挂的）。

**三条「不踩别人」的纪律**：

1. **只为「我们挂的」植物摘 buff** —— 若某株本来就被游戏挂着 `AttackSpeedDown`（埃德加二世的火球是
   0.5×/15s），**直接跳过，既不覆盖也不回收**。
2. **每次给一份新实例** —— `BuffComponent.EnterBuff` 是直接存进字典，**不克隆**。
3. **双保险过期** —— buff 自己的 `Step()` 到期自动摘除；插件同时显式 `DeleteBuff`，
   `Shutdown` 里也兜底摘一次（否则关掉 Mod 植物会永远开不了火）。

同时保留 `timeScaleInit = 0`，用于「暂停行动」的观感。两者互不干扰：
`PrepareCharacterTimeScaleForPhysics` 里 `timeScale = timeScaleInit` 之后才跑
`buffComponent.BuffUpdate(delta)`，且 `delta` 不受 `timeScale` 影响。

**未验证（诚实说明）**

- ⚠️ **没有真正启动游戏跑过。** 本轮最需要你实测的正是**前进**这件事：
  僵尸是否真的往左走、速度是否合适（25.53 px/s）、以及**每个步态周期结束时有没有倒跳**。
  - 若速度不合适：改 `nailong_skin.py` 的 `SPEED_TIER` 一处即可（2.0 = 普通僵尸的 2 倍）。
  - 若看到**周期性倒跳**：说明剪辑循环没有触发 `ResetGroundTracking`，
    那就得把锯齿改成「跨两个剪辑各半条」或缩短周期，告诉我现象我来调。
- ⚠️ **自制 `.dat` 的「动画静止」兜底逻辑仍未实机确认**（`forceLocalRender` / `forceCpuPoseRender`）。
  若奶龙一动不动，先看日志里有没有 `[NaiLong] 自制皮肤转本地 CPU 姿态`。
- ⚠️ **`LaughWalk` 用的是大笑立绘 + 正常步态**（即「边笑边走」）。如果你要的是
  「大笑期间完全不换立绘、就播普通 Walk1」（没有笑的表情），说一声 —— 插件里把
  `LaughClipName` 改成 `"Walk1"` 即可。
- ⚠️ **同屏多只奶龙同时大笑时，控场窗口是叠加延长**（取「最后一次触发 +3s」）。
- ⚠️ 每 10 秒笑一次、每次 3 秒 ⇒ **控场占空比 30%**。如果觉得太强，`LaughIntervalSec` 调大即可。

进游戏后如果哪条日志不对，把 `[NaiLong]` 开头的行发我，我按日志定位。
