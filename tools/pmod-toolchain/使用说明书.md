# PVZ 杂交版 Mod 编辑器 · 使用说明书

> 这是一个**在游戏外运行**的 Mod 编辑器。打开一个网页，点鼠标就能改游戏资源数值，
> 一键打包成 `.pmod` 并装进游戏，进游戏即可生效。
>
> 它和游戏内按 F3 弹出的那个「PVZ Mod 编辑器」**不是同一个东西**（那个是游戏自带的 GUI）。
> 两者产物格式完全一样，`.pmod` 互相兼容，你两边都可以改。

**本说明书只管"怎么用"。** 想了解 `.pmod` 二进制格式、C# 字段来源这类内部原理，看同目录的 `README.md`。

## 1. 启动

### 方式一：双击（日常用这个）

在 `ModWorkspace` 目录里双击：

```
start_editor.bat
```

浏览器会自动打开 `http://127.0.0.1:8765/`，编辑器就在里面。
关掉那个黑色命令行窗口 = 关闭编辑器。

### 方式二：命令行（想指定参数时）

```bat
start_editor.bat --no-browser           :: 只起服务，不自动开浏览器
start_editor.bat --port 8888            :: 换端口（默认 8765 被占用时用）
start_editor.bat --unpack "D:\别的解包目录"   :: 换解包目录
start_editor.bat --build                :: 不开界面，直接按工程文件打包+安装
```

### 方式三：不用 bat

```bash
C:/Users/yanxulin002/.workbuddy/binaries/python/versions/3.13.12/python.exe mod_editor.py
```

### 启动后先确认这两行

界面最上面会显示两个路径，**都要正常**：

| 显示 | 正常样子 | 不正常时 |
|---|---|---|
| 解包 `D:\zzz\pvzHE\解包\植物大战僵尸杂交版V0.28` | 后面没有红字 | 出现「← 不存在！」→ 用 `--unpack` 指定正确目录 |
| Mods `C:\Users\...\app_userdata\植物大战僵尸杂交版\Mods` | 后面没有红字 | 出现「← 不存在」→ 至少先启动过一次游戏 |

> 解包目录不存在的话服务会**直接拒绝启动**并提示你加 `--unpack`。
> 也可以用环境变量 `PVZHE_UNPACK` 指定，省得每次敲参数。

> ⚠️ **只监听本机（127.0.0.1），不会对外网开放。** 但**别同时开两个编辑器**（比如两个浏览器标签页）
> —— 工程文件是共享的，两边的自动保存会互相覆盖。

## 3. 五分钟上手：把豌豆变强

### 第 1 步 · 启动

双击 `start_editor.bat`，等浏览器打开。

### 第 2 步 · 选类别、选对象

1. 左栏「资源类别」点 **`子弹`**
2. 左栏搜索框输入 `PeaDefault`
3. 点列表里的 **`PeaDefault`**

中间会出现字段表单，底部日志记一条 `[Projectile] 137 个键`。

### 第 3 步 · 改数值

在「常规」分组里找这几行，把值改掉（改完点一下别处或按 Tab，值就生效）：

| 字段 | 原来 | 改成 | 效果 |
|---|---|---|---|
| `baseDamage` | 20 | **60** | 伤害 ×3 |
| `penetrateNum` | 3 | **8** | 能穿透 8 个僵尸 |
| `scale` | 1.0 / 1.0 | **1.6 / 1.6** | 子弹变大（两个框都要改） |

改过的行会变成**黄色高亮**，工具栏显示「已改 3 项」。

> 想让效果更明显？顺便把 `SnowPea`、`FirePea`、`GoldPea` 也这样改一遍。

### 第 4 步 · 确认产物

看右栏「产物预览」——它显示的就是即将打进包里的 `.tres` 原文。实际长这样：

```ini
[gd_resource type="Resource" script_class="TowerDefenseProjectileConfig" format=3]

[ext_resource type="PackedScene" uid="uid://dswe1rcdgitfr" path="res://Asset/Config/Projectile/Pea/Sprite/Pea/ProjectilePea.tscn" id="1"]
[ext_resource type="Script" uid="uid://bk3bi1tbywdrl" path="res://Resource/TowerDefense/Projectile/TowerDefenseProjectileConfig.cs" id="2"]
[ext_resource type="PackedScene" uid="uid://citia6twnyck" path="res://Prefab/Particles/Splats/PeaSplats/PeaSplats.tscn" id="3"]

[resource]
script = ExtResource("2")
name = "Pea"
projectileScene = ExtResource("1")
projectileObject = 301
splatScene = ExtResource("3")
hitEffect = null
collisionFlags = 1
catapultHeight = 400.0
baseDamage = 60.0            ← 你改的（原版没有这行，追加到末尾）
penetrateNum = 8             ← 你改的
scale = Vector2(1.6, 1.6)    ← 你改的
```

两个要点：

- **你没动的字段原样保留**（`projectileScene`、`splatScene` 这些引用都还在），
  换句话说**原版怎么写，产物就怎么写，只有你碰过的行会变**。
- 原版文件里**本来没有**的字段，改它会**追加到 `[resource]` 段末尾**（上面三行就是）。
  顺序不影响加载。

> 还有：第一行的 `uid="uid://b4e5lgjhpps8"` **不见了**——这是对的，故意的。
> 带着它进游戏会和内置资源 UID 撞车。而下面 `[ext_resource]` 里的 uid **必须保留**，
> 所以它们都还在。

### 第 5 步 · 填 Mod 信息

右栏「Mod 信息」：

| 字段 | 填什么 | 注意 |
|---|---|---|
| 名称 | `豌豆强化` | **会变成文件名**：`豌豆强化.pmod` |
| 标识 id | `pea_strong` | **建议只用英文、数字、下划线**（见 [§6](#6-mod-信息怎么填)） |
| 版本 | `1.0.0` | 随便，但依赖别的 Mod 时会被检查 |
| 作者 | 你的名字 | |
| 说明 | `豌豆伤害×3、穿透8、变大` | |

### 第 6 步 · 构建并安装

点 **「构建并安装」**。底部日志会出现：

```
开始构建…
打包成功: ...\ModWorkspace\dist\豌豆强化.pmod  (900 字节, 2 条目)
已安装到: C:\Users\...\app_userdata\植物大战僵尸杂交版\Mods\豌豆强化.pmod
进游戏后：按 F3 → Mod 工具 → 启用 → 「应用已安装 Mod 到当前游戏」
```

右栏「校验结果」显示 `FAIL 0 / WARN 0 / 共 13`（全绿）。
`共 n` 会随工程条目数增加，**只要 FAIL 是 0 就没问题**。

### 第 7 步 · 进游戏生效

启动游戏 →

1. 按 **F3** 打开「PVZ Mod 编辑器」
2. 找 **Mod 工具** 面板 → 找到你的 Mod → **启用**
3. 点 **「应用已安装 Mod 到当前游戏」**
   （提示「状态已保存；请使用"重新应用 Mod"，或重启游戏后生效」）
4. 再按一次 F3 关闭编辑器，进关卡看豌豆

以后每次改完再构建，记得**重新应用一次**（或重启游戏）。

## 4. 三种编辑动作

改过的字段行**鼠标移上去**，右侧会出现两个小按钮：

### ↺ 还原

撤掉这次改动，回到原版 `.tres` 的写法。

> 注意：如果这个字段**原版文件里本来就没有**（比如 `baseDamage`），还原之后它就**彻底不写了**
> —— 游戏会用 C# 类里的默认值（20）。所以在预览里 `baseDamage = 60.0` 会整行消失，这是正常的。

### ⌀ 用默认

**从 `.tres` 里删掉这个属性行**，让游戏回落到 C# 类的默认值。
和「还原」的区别：还原 = 回到原版文件怎么写；用默认 = 连原版那行也删掉。

> 只对**原版文件里确实写了**的属性有意义。原版没写的，点了会提示「已经是默认值」。
> 这类行会变成**蓝色高亮**，字段名后面的小字会多一个 `· ⌀ 删除`。

### 复制为新键（工具栏按钮）

以**当前选中的键为基底**，造一个全新的键。

举例：选中 `PeaDefault` → 点「复制为新键」→ 输入 `PeaDefaultMod` →
工程里多出一条 `新增 Projectile/PeaDefaultMod`，它继承了 `PeaDefault` 的全部字段，你可以随便改。

它走的是 `provides`（新增）通道，和「覆盖」是两条不同的路：

| | 覆盖 (overrides) | 新增 (provides) |
|---|---|---|
| 适用 | 改**已有**资源 | 造**新的**资源 |
| 键名必须 | **已经存在** | **不存在** |
| 反了会怎样 | 报「找不到原版资源」 | 校验报 `provide.exists` |

> 新增时编辑器会自动把 `.tres` 里的 `name` 字段改成新键名，避免和原版撞名。
> 你可以在表单里把它改成想要的中文/展示名。

工具栏另外两个按钮：**「全部还原」** = 清空当前条目的所有改动；**「只看已改」** = 只显示改过的字段。

### 删除一个条目

右栏「工程条目」里，鼠标移到条目上，右边出现 **✕**，点掉即可（不影响其它条目）。

## 5. 字段控件对照表

不同类型的字段给不同控件。**字段名下面那行小字**要会看，格式是：

```
baseDamage              ← 字段名（和 C# 里同名）
float · double · 默认    ← 控件类型 · C# 类型 · 值从哪来
```

第三段含义：

| 小字 | 意思 |
|---|---|
| `· tres` | 原版 `.tres` 文件里**显式写了**这个属性 |
| `· 默认` | 原版没写，现在显示的是 **C# 类的默认值**（改它 = 新增一行） |

控件对照：

| 字段类型 | 长什么样 | 写进 `.tres` 的样子 |
|---|---|---|
| `bool` | ☑ 勾选框 | `true` / `false` |
| `int` | 数字框 | `3` |
| `float` / `double` | 数字框（可小数） | `1.5` / `20.0` |
| `string` / `StringName` | 文本框 | `"Pea"` |
| `enum`（**字符串**枚举） | 下拉菜单 | `"Particles"` |
| `enumtype`（**整数**枚举） | 下拉菜单 | `301` |
| `vec2` | 两个数字框 | `Vector2(28.0, 28.0)` |
| `vec2i` | 两个整数框 | `Vector2i(0, 0)` |
| `color` | 色板 + alpha 框 | `Color(1.0, 1.0, 1.0, 1.0)` |
| `complex` | **灰色只读**，带 ⛔ | 原样保留，不动 |

**为什么有只读字段？**
它们是**数组 / 字典 / 资源引用**——比如 `projectileScene` 指向游戏内置的子弹场景、
`hitTargetEventList` 是一条事件链。这些东西改了会破坏引用，所以只能看不能改。
好在**你不改它，它就会原样保留**，不用管。

> 如果表单最下面出现一个「**其它属性（原版 .tres 自带）**」分组，
> 说明原版文件里带了不属于导出字段的属性，这里也只读展示。

## 6. Mod 信息怎么填

| 字段 | 用途 | 注意 |
|---|---|---|
| **名称** | 游戏 Mod 列表里显示的名字，**同时是打包文件名** | `豌豆强化` → `豌豆强化.pmod`。文件名里不能出现的字符（`\ / : * ? " < > \|`）会自动换成 `_` |
| **标识 id** | Mod 的唯一标识，被别的 Mod 依赖时用它 | 建议**手动填英文**（如 `pea_strong`）。留空或含中文时的自动生成规则见下方 |
| **版本** | `1.0.0` 这种 | 有依赖关系时会被检查 |
| **作者** | 随便写 | |
| **说明** | 一句话描述 | 显示在 Mod 列表里 |

### 关于 id 的自动生成（重要）

id 只能是 ASCII 字母/数字/`-`/`_`。名字里含中文时，编辑器会**保留能留的英文部分 + 挂一个名字哈希后缀**，
保证不同名字得到**不同 id**（否则两个中文 Mod 会撞成同一个 id，影响依赖判定）：

| 你填的名称 | 生成的 id |
|---|---|
| `豌豆强化` | `mod_0a0a5a` |
| `豌豆强化v2` | `v2_1faf81` |
| `我的 Mod 1` | `Mod_1_33268b` |
| `pea_strong`（纯英文） | `pea_strong`（原样保留） |
| `Pea.Overhaul` | `Pea_Overhaul` |

**能看到效果的地方**：右栏「产物预览」里展开 `mod.json`，`"id"` 那行就是最终结果。

> **建议**：名称写中文（好看、好认），id 手动写英文（好记、好分享）。
> 每次改动都会**自动保存**到 `mod_project.json`（400ms 防抖），关掉浏览器不丢。

## 7. 构建、安装、看校验结果

点 **「构建并安装」** 之后，会发生四件事：

1. 按工程条目渲染出文件（`.tres` 渲染出文本；音效条目用你选的替换文件）
2. 打包到 `ModWorkspace\dist\<名称>.pmod`
3. 复制到游戏 Mods 目录（`%APPDATA%\Godot\app_userdata\植物大战僵尸杂交版\Mods\`）
4. 跑一遍离线校验，结果列在右栏「校验结果」

> 第 1 步失败（比如有条目找不到原版资源）会**直接中止，不会写出任何文件、也不会安装**，
> 所以不用担心把游戏里的旧版本弄坏——构建失败 = 什么都没发生。

### 怎么读校验结果

摘要行是 `FAIL n / WARN n / 共 n`：

| 级别 | 意思 | 要做什么 |
|---|---|---|
| **FAIL** | **游戏会拒绝加载这个 Mod** | **必须解决** |
| WARN | 可能有风险，或离线核对不了 | 一般可忽略，但看一下没坏处 |
| OK | 通过 | 界面里默认不显示，全 OK 时只显示「全部 n 项通过」 |

常见的 FAIL 和处理：

| 校验码 / 报错 | 原因 | 怎么办 |
|---|---|---|
| `找不到原版资源: <类>/<键>` | 你**覆盖**了一个不存在的键 | 检查键名拼写；如果你是想造新资源，应该用「复制为新键」（走新增） |
| `provide.exists` | 你**新增**的键其实已经有了 | 改成覆盖（直接点那个键去改），或换个新键名 |
| `override.missing` | 同上，overrides 目标不存在 | 左栏确认这个键真的在列表里 |
| `entry.ambiguous` | 同一个 `类别/键` 出现了两份文件 | 工程条目里有重复，删掉一个 |
| `entry.executable` | 包里混进了可执行文件 | 正常流程不会出现，出现就是工程被改坏了 |
| `渲染失败` (预览区红字) | 有条目渲染不出来 | 看红字内容。音效条目没选替换文件就会报这个 |

> 改过校验器代码（`verify_pmod.py`）之后，**必须重启编辑器**才生效。

## 8. 进游戏启用与卸载

### 启用

1. 启动游戏 → 按 **F3** 打开「PVZ Mod 编辑器」
2. **Mod 工具** 面板 → 找到你的 Mod → **启用**
3. 点 **「应用已安装 Mod 到当前游戏」**
4. 关掉编辑器（再按一次 F3）

> 提示「状态已保存；请使用"重新应用 Mod"，或重启游戏后生效」是正常的——
> **改完重新构建后，要再点一次「应用」或重启游戏**才会加载新版本。

### 卸载

两种方式都行：

- 编辑器右栏「已安装 Mod」里点条目的 **卸载** 按钮（会弹一个确认框）
- 直接删掉 `%APPDATA%\Godot\app_userdata\植物大战僵尸杂交版\Mods\<名字>.pmod`

> 卸载只是删掉那个文件。**如果游戏里已经应用过它，记得再 F3 → 重新应用一次**
> （或重启游戏）才会真正恢复原状。

> 游戏**正在联机战斗**时会拒绝变更 Mod 环境，报「Mod 环境正在确认或用于联机战斗…」，
> 等打完再操作。

## 9. 替换音效这类"二进制条目"

**音效（`音效` 类别）** 不是 `.tres`，不能改数值，只能**整文件替换**。
点开一个音效键之后，中间不是字段表单，而是：

```
┌──────────────────────────────────────────┐
│      点击选择文件，或拖到此处              │
└──────────────────────────────────────────┘
```

- **拖一个 `.ogg/.wav` 进去**（或点击选择）
- 文件会存到 `ModWorkspace\.cache\uploads\`，工程里只记路径，不会把工程文件撑大
- 选好后会显示文件名和完整路径，还有「去掉替换文件」按钮

### ⚠️ 扩展名必须和原版一致

编辑器会在预览区给你**黄色警告**：

```
Audio/Apple：原版是 .ogg，替换文件是 .wav —— 扩展名不一致，游戏可能加载不了
```

Godot 是按**扩展名**挑解码器的，名字叫 `.ogg` 内容却是 wav，很可能加载失败。
**建议先用格式转换工具转成原版那个格式再替换。**

## 11. 常见问题与排错

### 启动相关

**双击 bat 闪一下就没了 / 提示找不到 python**
`start_editor.bat` 优先用 `C:\Users\yanxulin002\.workbuddy\binaries\python\versions\3.13.12\python.exe`，
找不到就退回系统 `python`。都没有的话，用记事本打开 bat 改 `set "PY=..."` 那行，指向你的 python。
bat 里加了 `pause`，正常报错时会停住让你看信息。

**浏览器没自动打开**
手动访问 `http://127.0.0.1:8765/`。或者用 `--no-browser` 后自己开。

**端口被占用**
```
start_editor.bat --port 8766
```
然后访问 `http://127.0.0.1:8766/`。

**提示「!! 解包目录不存在」**
用 `--unpack "D:\实际路径"`，或设环境变量 `PVZHE_UNPACK`。
注意：解包目录**不是游戏安装目录**，是解包出来的那个含 `Asset\` `addons\` 的目录。

**页面打开了但一片空白**
确认服务窗口还开着（命令行窗口关了服务就停了），然后按 Ctrl+F5 强制刷新。

### 使用相关

**某类别点开列表是空的 / 显示「缺」**
解包目录不完整，或者键指向的文件不在解包目录里。点一下「重建索引」试试。

**字段表单只有一行红字「找不到原版资源文件」**
说明这个键在**正式版**游戏里有，但你的**解包目录**里没有对应的 `.tres`。
换个键，或者换个完整的解包。

**预览区显示红字「渲染失败」**
看红字内容。最常见是音效条目还没选替换文件。

**改了值，预览没变**
点一下输入框外面（让光标离开），或按 Tab。改动是在 `change` 事件时生效的。

**「只看已改」勾上之后有一条蓝色高亮的行，没有黄色**
那是你点了「⌀ 用默认」的字段——它**算改动**（产物里那行会被删掉），所以也会显示出来。
鼠标移上去有「↺ 还原」可以撤销。

**id 明明是中文名，怎么变成 `mod_0a0a5a` 了**
id 只能用 ASCII。名称含中文时，编辑器会保留能留的英文部分并挂一个名字哈希后缀，
这样**不同名字一定得到不同 id**（否则两个中文 Mod 会撞成同一个 id）。
想自己控制就**手动填一个英文 id**（比如 `pea_strong`）。规则表见 [§6](#6-mod-信息怎么填)。

**改完游戏里没反应**
① 确认「构建并安装」成功（日志有 `已安装到:`）；② 游戏里 F3 → Mod 工具 → **重新应用**；
③ 还不行就重启游戏；④ 注意联机战斗期间拒绝变更。

**同时开了两个编辑器标签页，改的东西乱了**
工程文件是共享的，两边的自动保存会互相覆盖。**只开一个。**

**点了「子弹」（或任何类别）之后，左栏下面看不到「搜索键名…」输入框**
这是 **0.28 早期版本的一个布局 Bug**，已修复。如果你用的是旧版 `mod_editor_ui.html`，
表现是：左栏「资源类别」把整个左栏占满，「键」区块和搜索框被挤到窗口底部、被输出栏盖住
——**窗口越矮越明显**（浏览器可视高度 ≲800px 时必现；1440×900 那种大窗口看不出来）。

修复办法就是**用当前版本的 `mod_editor_ui.html`**，并把编辑器页面**刷新一次**（Ctrl+F5）。
修好之后的正常表现是：左栏按约 38% / 62% 分成上下两块，上面是「资源类别」，
下面是「键 N/总数」+ 搜索框 + 键列表，各自独立滚动，任何窗口高度下搜索框都在可视区内。

> 顺带修掉的同类问题：窗口较矮时右栏「构建并安装」按钮会被下一个区块的标题盖住、点不到。
> 现在右栏整体可以上下滚动，所有区块都不再互相挤压。

**窗口调小之后，右栏的「校验结果 / 已安装 Mod」要往下滚才看得到**
这是修复后的**预期行为**：右栏内容比窗口高时它就整体滚动，而不是把区块压扁到 1px。
用鼠标滚轮或拖动右栏右侧滚动条即可。左栏的类别列表和键列表也是各自滚动的。

### 边界

- **托管代码 Mod**（带 `Runtime/ModAssembly.dll` 的 C# Mod）编辑器**不做代码部分** ——
  它照样能把包里的 `Runtime/ModAssembly.dll` 当普通文件读写、导出、校验，
  但**生成/编译这个 DLL 需要 .NET 工具链**，要手写（配方与约束见 `README.md` §2.6；
  样板：`runtime_src_plant/` + `植物Mod-超级机枪射手.md` §3）。
- **游戏内实测**：编辑器只能保证产物**格式合规**（校验全绿），
  具体生效效果还得你进游戏看。
- 界面只是个普通网页，**系统自带浏览器就行**（Edge / Chrome / Firefox），不用装任何插件。

## 12. 工程文件与快捷键

### 文件位置

| 文件 | 说明 |
|---|---|
| `mod_project.json` | **你的工程**。所有条目和 Mod 信息都在这，自动保存 |
| `dist\<名称>.pmod` | 打包产物 |
| `.cache\uploads\` | 拖进来的替换文件（音效等） |
| `.cache\uid_index.json` | 资源索引缓存，删了会重建（约 5~7 秒） |
| `.cache\enum_index.json` | 枚举缓存 |

### 工程迁移 / 备份

把 `mod_project.json` 复制走就是备份，改坏了复制回来即可。

换台机器时要注意：条目本身存的是**「类别 + 键名 + 改动值」**，不含绝对路径，
所以只要新机器上的解包目录能找到同样的键，项目就能直接用（解包目录换位置就用 `--unpack`）。
**唯一例外**：音效这类条目会记下你选的**替换文件的绝对路径**，
换机器（或挪动了那个文件）后需要重新拖一次文件。

### 快捷键

| 快捷键 | 作用 |
|---|---|
| <kbd>Ctrl</kbd> + <kbd>S</kbd> | 立即保存工程（平时 400ms 自动保存，不用手动按） |

### 顺手的小技巧

- **左栏搜索框支持部分匹配**，输入 `pea` 就能过滤出所有名字含 pea 的键
- **右栏「产物预览」是最好用的自检**：每次改动都看一眼，确认改对了、没多写、没漏写
- 想批量改一类资源（比如所有豌豆）就**每个键各加一条工程条目**，一次构建全部生效
- 改之前**先复制一份 `mod_project.json`**，改坏了能退回去
- `dist\` 里的旧产物**不会自动清理**，攒多了可以自己删
