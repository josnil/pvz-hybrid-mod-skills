## 射击驱动链（关键）
`FireComponentDefinition`（.tres）→ `FireComponent`（Runtime）
- `fireIntervalBase/fireInterval/fireIntervalOffset`（默认 1.5/1.5/0.1）
- `fireNum`（默认 1）+ **`fireNumAtOnce`（默认 false）** ← 决定「一次打 N 发」
- `fireCheckList : Array<FireComponentCheckConfig>` —— 命中判定 → `fireProjectileList : Array<FireComponentFireProjectileConfig>` —— **实际发射条目**
- `FireComponentFireProjectileConfig` 字段全集（仅 8 个）：
  `checkProjectileId, firePosId, speed, dir, offsetLine, fireNumSkip, fireEventNeed, projectileFlip`
  **没有「概率」「角度抖动」「延时」字段。**

### FireConfiguredVolley（FireComponent.cs:3413）
```csharp
if (!fireNumAtOnce) { Fire(); return; }        // 逐发：一串动画事件各触发一发
int num = Math.Max(1, fireNum);
for (int i = 0; i < num; i++) { currentFireNum = i; Fire(i == 0); }   // 一次齐射 N 发
```
`Fire()` 内：`velocity = config.speed * Vector2.FromAngle(DegToRad(config.dir))`
→ **`dir` 单位是度，0=+X（右）。**
→ `CreateProjectile` 里 `vector = velocity * Mathf.Sign(parent.Scale.X * ...)` → **朝向左翻自动镜像，无需写两套。**

### 扇形散射的真实做法（Starfruit 范式）
`Starfruit` 5 条 `FireComponentFireProjectileConfig`，各带 `dir = 330/270/180/90/30` + `firePosId` 0..4。
→ **要「7 颗豌豆」就是 7 条 config；要「±15° 散射」就把 dir 写成扇形。全是数据，可行。**

### 多行 / 双向范式
- `ThreePeater`：3 条 config，`offsetLine = -1/0/+1`（走**不同行**）。
- `SplitPea`：`fireNum = 2` + `fireNumSkip = 1`（第 0 发用一条、第 ≥1 发用另一条）+ 反向 `speed = -300`。

## ⚠️ 纯数据做不到的部分：10% 概率大招
- `FireComponent` 里**唯一的随机源**是 `OnFireVolley(ulong randomSeed)`，且 seed 由
  `NetworkDeterministicSeed.ForCharacterEvent(syncId, seq, 4051590893)` 确定性生成 → 主播/客户端一致。
- `FireComponent` **本身没有任何 `RandfRange`**（全文件只在子类 `TowerDefensePlantGatlingPea.FireVolley` 里出现）。
- 状态机 `FireComponentStateMachine` 只有 `idle/attack/restore` 三态 + `ToIdle/ToAttack/ToRestore`，**无概率守卫字段**（`GuardDefinition = null`）。
- **结论：`10% 触发 + 5 秒内 300 发` 必须写 C#**（要么自定义 Plant 子类，要么托管 Mod 程序集）。
  纯 `.tres` 只能表达「每次齐射都散射」，表达不了「10% 概率进入 5 秒爆发态」。

## 包结构硬约束（ModLoader.cs）
1. `TryInferCharacterScene`：路径必须**恰好 6 段** `Resources/Characters/<Category>/<Key>/Scene/<Key>.tscn`，
   且文件名 == 目录名 == Key。Category ∈ {Plants,Zombies,Props,Vases,Mowers,Items,Graves,Craters}。
2. `IsCharacterPackageDependency`：`Resources/Characters/<Cat>/...`（**≥5 段**）下的一切都算包依赖 → sprite/config/componentSet 都放这里不会报 unsupported。
3. `PrepareSafeCharacterPackage` + `SanitizeCharacterTextResource`：
   - 包内**禁止** `.scn/.res`
   - `.tscn/.tres` 里**禁止**内嵌 `type="GDScript"/"CSharpScript"`
   - `[ext_resource ... type="Script" ... path=...]` 若 **不以 `res://` 开头** → `.tscn` 会被**剥掉该脚本引用**（并写回文件！）；`.tres` 则直接**拒绝**。→ **一律用 `res://` 绝对路径引用原版脚本。**
4. `CharacterRequiresCompanion`：只有场景根带 `mod_character_script_binding = "CompanionOnly"` 才要托管程序集。引用原版 `res://` 脚本 → **不需要伴生运行时**。
5. `Provides`/`Overrides`：新键走 `provides`，覆盖已有走 `overrides`；同 (category,key) 出现两次 → `ambiguous`。

## Packet（卡片）字段（TowerDefensePacketConfig）
`saveKey, unlockCheckList, name, describe, handbookDescribe, handbookStory, packetAnimeClip, packetAnimeOffset, packetAnimeScale, characterConfig, type, override`
- `name/describe/...` 是**翻译键**，取值来自 `Asset/Translate/Translate.csv`（`key,en,es,zh`）
- 例：`TOWERDEFENSE_PLANT_GATLINGPEA_NAME` → zh `机枪射手`
- 机枪射手卡片 `type = 7`，解锁条件 `packetBankName="GeneralPlant", category="Original", num=10`
- 卡片路径规则：`Resources/Cards/<Key>.tres` → category `Packet`，key = 文件名
